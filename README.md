# BassChart Studio

面向贝斯手的本地备曲工作台。最新使用重点是 **贝斯主要音名与三轨独立编辑**：贝斯音名在上、手写加花在中、可编辑歌词在下。三轨共用拍点，各自定位和排版；顶部也可切换查看旧工程和弦。中间轨只显示用户手写数字，不混入自动贝斯音符；旧音符和标记数据继续保存在工程中。

2.1 是前一轮功能升级的名称，不表示全部 AI 模型已通过真实歌曲精度验收。用户提供的[升级需求原文](docs/UPGRADE_2_1.md)保持原样；最新使用范围、[开发路线图](docs/ROADMAP.md)与[验证报告](docs/TEST_REPORT.md)分别记录目标、实现范围和测试证据。BPM、调性、和弦、段落与歌词时间候选都需要试听核对。可以继续使用 LRC 与手工歌词，不必先安装 AI 模型。

## Windows 11 启动

查看版本记录、保存源码及发布 GitHub 私有仓库，请参阅[版本保存指南](docs/VERSION_HISTORY.md)。Git 记录从 2026-10-21 的当前源码快照开始；歌曲与校谱工程需另外备份。

准备 Python 3.11 或更新版本，以及 Node.js 20.19+ 或 22.12+。Python 需要能通过 `py` 或 `python` 找到，Node.js 需要能通过 `npm.cmd` 找到。

1. 双击项目目录中的 `start.cmd`。
2. 首次启动会创建本项目的 `.venv`，安装基础 Python 与前端依赖，并构建界面。首次安装需要联网。
3. 浏览器会打开 <http://127.0.0.1:8000>。保留启动窗口；按 `Ctrl+C` 停止服务。

后续启动会检查依赖文件与界面源码的内容，通常可跳过依赖安装和界面构建。启动脚本不会自动安装或下载大型音频模型。

在 PowerShell 中也可启动：

```powershell
cd D:\zzMUSIC\BassChartStudio
.\start.ps1
```

可选启动参数：

```powershell
.\start.ps1 -NoBrowser          # 不自动打开浏览器
.\start.ps1 -Port 8001         # 更换端口
.\start.ps1 -Reinstall         # 重新检查并安装基础依赖
.\start.ps1 -Rebuild           # 强制重新构建界面
```

如果系统执行策略限制直接运行 PowerShell 脚本，使用 `start.cmd`。它仅为这一次启动调用设置执行策略，不修改系统的永久设置。

## 使用流程

首页提供“导入音频”和“导入歌词”两个入口。音频可拖入或选择；歌词可粘贴或读取 TXT/LRC。新导入完整原曲后自动启动贝斯分析。打开原创合成演示工程，可先体验播放器、歌曲结构、歌词对位和导出。演示内容是产品示例，不代表真实歌曲的模型识别效果。

默认流程为“原曲 → 分离贝斯 → 增强贝斯音量 → 提取主要音名”。按有效网格的半小节窗口选取稳定音，合并相邻同音，静音或缺少可靠音高的位置留白；短促经过音留给手写轨。顶部的 A、C、E 是低音音名，不代表 A、C、E 大和弦。旧工程不会自动改谱，点击“分析贝斯音名”后才生成新轨；原和弦保留，可在“谱面设置 → 顶部轨道”切换。

只有在导入类型明确选择“已经分离的独立贝斯轨”时才跳过分离。完整原曲必须取得有效贝斯轨；分离或模型失败会报告原因，不改用混音生成音名。重试默认复用有效分轨，也可在分析设置中选择重新分离。分轨成功后立即保存，即使后续分析失败仍可试听。

增强版采用整轨线性增益，最多提升 12dB，采样峰值不超过 −3dBFS，采样率、声道数与帧数保持不变；静音不提升。原始贝斯分轨保留，试听默认使用增强版，可在版本菜单切换，并通过命令面板下载原版或增强版。增强主要改善试听，不保证提升音高检测准确率。重新分析保留人工音名、删除记录、人工节拍网格、歌词和手写加花。

独立贝斯轨没有人声，不能从中识别歌词。此时导入 LRC 或粘贴 TXT，再校正时间；要使用可选 AI 歌词识别，仍需准备对应歌曲的真实 Vocals。歌词和单轨应来自同一个版本并保持相同起点，裁剪过的单轨需要另外校正时间偏移。

可以先准备歌词，再选择音频；原文会带入新工程。TXT 按原分行生成片段，从零秒按文字宽度紧排，不再均分整首歌；LRC 保留已有时间标签。初排只计算一次，字号和窗口变化不会重排保存的时间。紧排不是已识别的演唱时间，需要用户手动对齐；已有工程的歌词不会自动重新紧排。

导入自己的音频后，先检查音频时长和可用的分析条件，再确认 BPM、拍号、首拍及调性。通过小节和拍点组织和弦事件；歌词片段通过时间戳关联节拍网格，允许同一小节内多个和弦。修改候选结果后，保存工程并导出排练资料。工程数据与音频保存在 `backend/data/projects/`；各工程的 `project.json` 是完整数据来源，`index.sqlite3` 保存曲库元数据索引，可从工程 JSON 重建。换电脑或备份时请保留整个工程目录。

双击歌词或选中后按 F2 直接编辑。句首按 Space 向后调整四分之一拍，Backspace 删除前方空白、向前调整四分之一拍；不足四分之一拍时仅消耗剩余间距，不往正文写入空格。前方空白耗尽后，500 毫秒内双退格与前句合并；刚用于删除空白的按键不会触发合并。正文内部仍可双空格拆分，普通空格及中文输入法保持文字编辑。Ctrl+Enter 在光标处拆分，Ctrl+Shift+Enter 合并；Enter 完成编辑，Esc 取消尚未提交的文字。

拖动歌词先只移动当前句，碰到后一句文字才将其向后推，推移遇到空隙就停止。向左移动不会拉动后句。碰撞按文字实际宽度判断，LRC 结束时间内的静默仍可作为空白编辑。拖动可跨小节、段落，预览与保存使用同一组宽度；每个受影响片段的起止时间平移、时长不变，和弦与加花保持独立。达到歌曲边界时限制本次移动，不截断歌词。删除整句留下空白。

点击中间加花轨的空白拍位，输入 `1234` 后按 Enter 或勾号写入。选中数字可以设置下划线与上下八度点：无横线是四分音符，一条是八分，两条是十六分；上方点为高八度，下方点为低八度，最多两个点。`0` 为休止。修改时值、删除数字只收拢本组后续数字；拖动任一数字移动整组，不改另外两轨。中间轨默认空白，重新分析不会生成或覆盖手写内容。数字过多时，整组限制在所属和弦到下个和弦之间显示，先收紧间距、适当缩小，再在该和弦下换行；没有和弦时使用当前小节。屏幕至少 12px、打印至少 9pt。紧凑显示保留实际演奏时间、下划线和八度点，点击仍定位原时间。

选中手写数字后可添加红色演奏法：上滑、下滑、切音、闷音/死音、击弦、勾弦、延音线与重音。相同操作再次执行即取消。滑音、击勾弦及延音线连接同组下一个数字；休止和死音不能连接，延音线还要求同音、同八度且时间相接。删除端点或修改数字时清理失效连接，不会自动跨过被删除的音。符号不改变音符时间。

歌词默认 20px，可独立调至 14–32px；打印默认 12pt，可调至 10–20pt。谱面设置中可分别调整歌词深灰、顶部音名深蓝、加花深绿、标记红色，或恢复默认。字号与颜色保存在工程中，HTML/PDF 采用相同设置；字号变化只影响排版，不改歌词时间。打印可选择彩色或黑白，以及 A4 横向或纵向；打印窗口应使用同一方向。

修正 BPM、拍号、首拍或逐拍网格时，歌词、贝斯音名、和弦及加花数字保留实际音频时间，再重新关联小节与拍点。移调更新顶部音名，不改手写数字，也不改变原音频音高。

**试听速度与 BPM 独立。** 底部 `0.5×` 只改变试听速度；谱头 BPM 用于校正节拍网格。密集和弦换行显示，变化拍点保持独立，不能靠字符空格推算时间。

点击小节号或歌词可以定位音频。播放时，谱内竖线跟随当前拍点。字号、每行小节数、和弦级数和自动跟谱集中在“谱面设置”菜单。可使用循环与变速试听核对和弦变化。

底部 **A/B** 设置任意循环：先定位起点点击 A，再定位较晚的终点点击 B；播放时在两点间循环。点击循环按钮关闭后可继续正常播放。段落标题旁的循环按钮仍可一键循环整段。

重复段落可从段落编辑弹窗复制当前顶部轨道，填写目标开始小节后执行。贝斯模式复制音名，旧和弦模式复制和弦；目标范围被替换并保留相对拍点，另外两轨保持独立。复制操作可撤销/重做。

谱面提供三轨排练谱与结构总览。PDF、互动 HTML、JSON 保存手写加花及其符号；LRC 只导出歌词时间。旧贝斯音符、根音候选和旧 Fill 标记不自动迁入手写轨。

在导出 PDF 时，使用界面的打印功能，再在浏览器打印窗口中选择“另存为 PDF”；A4 方向及黑白打印可在打印窗口调整。当前不是后端 PDF 渲染服务。

## 当前范围与限制

默认三轨谱用于快速备曲，贝斯音名与音阶级数可切换，旧和弦视图保留和弦级数。所有轨道均以实际音频时间与拍点定位。手写数字是用户演奏提示，不生成 MIDI、TAB 或 AI 加花。

分析说明、歌词时间校正及高级音轨选项默认收起；常用入口为试听、编辑贝斯音名、导入歌词、手写加花、保存和导出。

编辑停止约两秒后自动保存；分析任务进行时暂停，任务完成后继续保存。保存失败或版本冲突会提示，未保存修改仍留在界面。撤销/重做记录当前会话的编辑，重新打开工程不恢复临时历史；重新分析保护已经保存的人工数据。旧工程使用兼容默认字段。

所有页面均可按 **Ctrl+K 搜索命令**、**F1 查看快捷键**。输入歌词时，空格和方向键优先用于文字编辑。

## LRC 时间歌词与网易云

LRC 是带逐句时间标签的歌词文本。例如下面两句分别从音频第 12.5 秒和第 18.2 秒开始：

```text
[00:12.50]第一句歌词
[00:18.20]第二句歌词
```

它通常不是逐字时间。当前应用不能仅凭网易云歌曲链接自动取词；取得标准 `.lrc` 后可以导入。从网易云复制的普通歌词走 TXT 粘贴与校对，仅把 `.txt` 改成 `.lrc` 不会添加时间。

可在 [LRCLIB](https://lrclib.net/) 按歌名与歌手查找，或使用其官方客户端 [LRCGET](https://github.com/tranxuanthang/lrcget/releases)。LRCGET 提供 Windows 安装包，选择本地音乐文件夹后尝试匹配，并在歌曲旁保存同名 `.lrc`。库中可能没有对应歌曲，或只有无时间的普通文本；LRCLIB 的 `syncedLyrics` 是 LRC，`plainLyrics` 是普通文本。[官方说明](https://lrclib.net/docs)

试听确认对应歌曲版本；Live、翻唱、剪辑版的前奏和时长可能不同。找不到现成时间歌词时，可在应用内逐句校正后导出 LRC。

## 可选 AI 歌词识别与对齐

歌词区以用户原文为主列，AI 识别文本为副列，显示差异、置信度及候选时间。先“识别音频歌词”可查看初稿，“按原文对齐”生成逐句候选；单句按钮重新识别并对齐该句。可靠候选会更新尚未确认的 TXT 占位时间，低可靠或缺失片段标为待对齐。LRC 的真实时间标签及手动校正时间受到锁定保护，用户试听后可主动改用候选时间。AI 初稿不会自动修改用户文本。

导入原文的空白、换行和 LRC 标签完整保留，并原样传入对齐请求。匹配时仅从正文候选中剥离合法 LRC 时间标签与标准元信息；同一句的多个时间标签依照各自时间关联。TXT 的外层空白不会造成重复歌词，已经锁定的歌词文字与时间继续保留。

必须先准备真实可用的独立 **Vocals 人声音轨**；没有人声的贝斯单轨不能用于歌词识别。推荐在已经安装基础依赖的项目 `.venv` 中增加可选依赖，然后重启服务：

```powershell
# 项目根目录；先停止当前服务
.\.venv\Scripts\python.exe -m pip install -r requirements-ai.txt
.\start.ps1
```

后端优先使用自身 Python 环境内可加载的 faster-whisper；否则通过独立歌词进程检查项目 `.venv`，也可用 `BASSCHART_AI_PYTHON` 指向另一个已安装基础及 AI 依赖的 Python。这样可以保留原有 Demucs 环境。自定义时从同一终端启动服务：

```powershell
$env:BASSCHART_AI_PYTHON = 'D:\tools\bass-ai\Scripts\python.exe'
# 该环境需先安装 requirements.txt 和 requirements-ai.txt
.\start.ps1
```

默认 CPU、`int8`、`tiny` 模型。首次真实识别若没有缓存，会联网下载权重；后续使用缓存。识别设置可选中文、英文、日文、自动判断及模型大小。基础启动不自动安装这一依赖。缺少人声、模型不可用或任务失败时会显示具体原因，不生成伪造成功结果。

当前根据识别字词时间匹配用户文本；部分片段内时间仅为近似候选，不属于 WhisperX 音素级强制对齐。模型默认缓存于 `backend/data/models/hub/`；可用 `BASSCHART_WHISPER_CACHE` 指定缓存位置。

本轮环境的初始 tiny 权重下载受到网络阻塞，尚未完成真实 ASR 推理与精度验证。受控适配器测试、匹配规则测试或界面通过不表示真实歌唱识别成功；取得模型后仍需使用实际人声轨试听与校正。

导出的 JSON 用于保存可编辑工程；独立 HTML 可查看排练谱并选择本机音频播放，两者都不嵌入音频。导入 JSON 时，谱面数据关联到当前已导入的音频工程；跨设备使用请先导入对应音频，再导入 JSON。可用的独立音轨可另行下载为 WAV。不要将简单音高检测或演示音轨误认为 AI 分离或转写结果。

## 音频与可选模型

WAV 是最容易排查问题的输入格式。MP3、FLAC、M4A 的解码条件与本机可用的音频工具有关。当前后端先检查工作目录中已有的 `D:\zzMUSIC\ffmpeg-2025-10-16-git-cd4b01707d-essentials_build\bin\ffmpeg.exe`，找不到时再检查 `PATH`。换电脑时，可将已有 `ffmpeg.exe` 所在目录加入当前终端的 `PATH`，再从同一个终端运行启动脚本；无需为本工程移动原有 FFmpeg 安装。

例如已有工具位于 `D:\tools\ffmpeg\bin`：

```powershell
$env:PATH = 'D:\tools\ffmpeg\bin;' + $env:PATH
.\start.ps1
```

Demucs / HTDemucs 属于额外安装项，其权重可能需要首次联网下载，也会消耗较多运行时间和磁盘空间。基础界面与工程编辑可以在没有分离模型时使用；未安装模型时，应遵循界面提示，不会把原曲复制品标注为已完成音轨分离。高精度音素级强制对齐尚未接入。

基础应用可使用 Python 3.13；Demucs 与 PyTorch 等音频模型依赖可能需要独立 Python 3.11 环境。启动器继续使用项目 `.venv` 运行主服务，并可以复用已经安装 Demucs 的其他 Python，无需迁移现有模型环境。

如果已显式设置 `BASSCHART_DEMUCS_PYTHON`，启动器保留该路径；否则，当项目 `.venv` 缺少 Demucs 时，会只读检查 `PATH` 中可用的真实 `python.exe`，排除 WindowsApps 启动别名，并对可导入 `demucs.separate` 的环境设置本次启动使用路径。健康检查与实际分离使用同一个解释器。显式路径无效时会报告不可用，不自动换到别的环境。健康检查的依赖可用不表示模型权重已下载或实际分离质量通过。

已安装 Demucs 时，可从启动服务的同一终端指定其 Python：

```powershell
$env:BASSCHART_DEMUCS_PYTHON = 'D:\tools\demucs\Scripts\python.exe'
.\start.ps1
```

若还没有兼容的 Demucs 环境，可建立独立环境；先完成基础启动并停止服务：

```powershell
py -3.11 -m venv .venv-model
.\.venv-model\Scripts\python.exe -m pip install -r requirements.txt
.\.venv-model\Scripts\python.exe -m pip install demucs
$env:BASSCHART_DEMUCS_PYTHON = (Resolve-Path .\.venv-model\Scripts\python.exe).Path
.\start.ps1
```

模型依赖若安装失败，请根据所选模型的官方说明选择兼容的 Python / PyTorch 版本；这些依赖不属于基础安装的保证范围。分离失败和未安装模型会在分析结果中提示，不会影响已保存谱面的查看和人工编辑。独立歌词环境需同时具备 `requirements.txt` 的基础依赖，不是仅安装 faster-whisper 即可；可以与独立 Demucs 解释器分别配置。

## 工程结构

```text
BassChartStudio/
├─ backend/            Python / FastAPI 后端，app.py 导出 app
├─ frontend/           React / TypeScript / Vite 界面
├─ docs/               完整路线图、验证报告与验收证据
├─ requirements.txt    基础 Python 依赖
├─ requirements-ai.txt 可选 faster-whisper 依赖
├─ start.ps1           安装、构建与本地启动
└─ start.cmd           Windows 双击入口
```

生产界面由 FastAPI 提供，服务只监听 `127.0.0.1`。浏览器界面调用同一台电脑的后端；音频分析在本机运行。基础依赖安装和可选模型下载需要网络，应用没有默认云端音频上传流程。

开发时可以分别运行后端与前端：

```powershell
# 项目根目录，完成基础依赖安装后
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --reload

# 另一个终端
cd frontend
npm.cmd run dev
```

开发验证命令如下。后端测试位于 `backend/tests/`；前端工具测试涵盖音乐、速度网格与数字谱规则。

```powershell
# 项目根目录
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -v

# 前端目录
cd frontend
npm.cmd test
npm.cmd run build
node scripts/verify-lyric-alignment.mjs

# 本地服务已启动时运行浏览器检查，需要本机 Microsoft Edge
node scripts/verify-ui.mjs
```

首次启动已在独立 `.venv` 中完成验证。测试环境的依赖安装曾因无响应的系统代理失败，测试时临时使用 `NO_PROXY='*'` 排除该问题；日常启动请依照实际网络配置排查，启动脚本沿用已有代理设置。已有本地服务使用 8000 端口时，再启动会提示端口占用，可直接访问已运行页面或选择其他端口。

## 常见问题

- **启动窗口报告缺少 Python / npm：** 安装相应运行环境后，关闭并重新打开终端，再启动工程。
- **8000 端口被占用：** 关闭之前启动的服务，或用 `start.ps1 -Port 8001`。双击入口可通过命令行传递同样参数。
- **第一次安装失败：** 检查网络连接和依赖安装错误，修复后再次启动。若报代理连接失败，检查 Windows 系统代理、终端的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 及 pip/npm 代理设置，确认代理地址端口正确且服务正在运行；修正过期设置后重新打开终端并重试。启动脚本沿用已有代理配置，仅在成功完成安装后记录缓存标记。
- **音频读取失败：** 先确认文件能正常播放，检查 FFmpeg，再尝试导出为 WAV。
- **自动结果与原曲不符：** 先校正节拍网格与调性，再修改和弦、歌词片段和贝斯音符；保存 JSON 工程保留人工修改。

实际演出前，请完整试听并校对节拍、段落、和弦变化与停顿。这个版本用于缩短整理谱面与校正的过程，尚不能保证对任意真实歌曲完成精确自动扒谱。
