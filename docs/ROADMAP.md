# BassChart Studio 开发路线图

版本：原始 V1.0 规划、V0.1 历史交付、2.1 功能迭代与最新贝斯音名工作流对照。更新日期：2026-10-20。

## 产品目标

在 Windows 11 上，以本地优先的方式，把导入音频、分离音轨、节拍与和声候选、歌词对位、贝斯线整理和排练谱编辑连接到同一工程。首要目标是快速形成可演奏的谱面，随后用试听与人工校正提高可靠性。

自动歌词转写、复杂爵士和声、精确演奏法识别不作为第一版硬性前提。AI 候选、原曲实际标记和 AI 建议必须区分；重新分析必须保留已保存的人工修改。

## 最新使用范围：贝斯音名、彩色谱面与演奏标记

新导入完整歌曲自动执行分离贝斯、生成独立增强 WAV、按半小节提取主要音名。有效分轨可复用，分离失败停止并提供重试，不使用完整混音替代。独立贝斯输入需明确选择。增益最多12dB、采样峰值不超过−3dBFS，原分轨保留。主要音名使用独立 `bassEvents`，与旧 `chords` 分开；旧和弦可切换查看，音名不代表完整和弦。

顶部音名、中间手写加花、底部歌词保持独立。歌词默认20px、打印12pt，有独立字号及四类配色设置，并保存到 `scoreStyle`；彩色/黑白及 A4 方向用于 PDF 与 HTML。手写加花支持上滑、下滑、切音、闷音、击弦、勾弦、延音线和重音，快捷键/按钮/命令共用操作。连接保存目标数字 ID，修改或删除端点清理失效连接，不改变实际演奏时间。

本轮验证与限制记录在 [TEST_REPORT.md](TEST_REPORT.md)。真实曲库准确率仍需建立人工基准；单条真实分轨或合成样本测试不能替代精度评估。已有工程不会自动重新分析或重新安排歌词。

## 三轨独立编辑（前一轮范围）

已实施用户确认的三轨计划：和弦在上、手写加花在中、歌词在下。每行共用拍点，三轨各自排版及拖动；歌词与加花可跨小节，不受单个小节剩余宽度限制。

TXT 保留原分行，从零秒按文字宽度紧排一次；LRC 保留时间标签。双击歌词直接编辑；句首空格/退格调整四分之一拍，正文双空格拆分，前方空白耗尽后双退格合并。拖动只移动当前句，发生文字碰撞时才逐句向后推移，遇到空隙停止；不使用LRC结束时间占满句间空白，不截断文字或改变其他轨道。

手写加花以独立 `manualFills` 保存，支持 `0–7`、下划线0/1/2、上下八度点、组内节奏重排、删除及整组拖动。不读取旧自动 `notes`，不生成 MIDI/TAB。BPM 校正和移调保留手写内容，分析和识词保护人工集合，旧客户端缺省保存不清空。

长组加花限定在所属和弦范围内显示；收紧间距、适当缩小后仍放不下则换行，实际时间和符号不变。统一快捷键通过 Ctrl+K 搜索操作、F1 查看帮助；普通文字输入、中文输入法、表单与谱面对象分上下文处理。

PDF/HTML/JSON 输出手写加花，LRC 只输出歌词。本轮前端77项、页面13组、数据保护14项和既有工作流3组通过，完整证据见 [TEST_REPORT.md](TEST_REPORT.md)。旧工程不会自动重新排列歌词。

## 完整原曲与简洁歌词和弦谱（前三轨迭代记录）

按用户最新要求，工作台采用浅灰、白色、蓝色及留白，常用入口集中在试听、歌词导入、和弦校正、保存和导出。谱面只保留歌词、和弦、拍点及段落，移除数字谱、TAB、根音与加花编辑入口；字号、每行小节数和级数切换收进“谱面设置”。已有 `notes`、`markers` 数据继续保存在工程中，[2.1 升级需求原文](UPGRADE_2_1.md)不改写。

分析来源默认 `original` 完整原曲，默认不转写音符；Bass 用于独立试听。`bass` 和 `uploaded_bass` 仅校正节拍，不将低音根音或经过音写入和弦列表。旧 `E?` 等候选从谱面、播放提示和 HTML 隐藏，人工填写的完整和弦保留。完整和声仍需原曲或人工校正。

单轨节拍更新保留已有和弦的绝对音频位置，再关联新网格；人工网格仍受到保护。候选首拍若晚于已有和弦，保留原网格并给出说明，避免静默挤到首拍。首拍前的歌词也会显示且保留原时间。首页和曲库的 PDF 导出先呈现曲谱，避免空白页。LRC/TXT、歌词原文、音符及个人标记继续保留。

本轮后端 66 项、前端工具 42 项、简洁界面与速度/打印专项 12 项、歌词显示 6 项和素材/循环/复制 3 组通过；A4 纵横与 HTML 打印样本均实际渲染目视。用户确认《红色高跟鞋》为完整原曲，已备份并按原曲重新分析；25 个歌词片段和原文保持不变，低音候选已替换，实际页面无数字音符或 Fill。和弦仍为 Chroma 模板初稿，未建立真实歌曲准确率。证据见 [TEST_REPORT.md](TEST_REPORT.md)。

2.1 验收以实际工程可编辑、原文与人工修改受保护、缺少模型时错误清晰为底线。52 项后端、37 项前端工具与 6 项歌词显示语义检查验证实现规则，不能替代真实 ASR、分离与音乐精度测试。后端与最终界面/打印结果见 [TEST_REPORT.md](TEST_REPORT.md)。

歌词原始文本保持逐字内容及空白换行。合法 LRC 标签与标准元信息只在匹配正文时剥离，多时间标签按实际时间关联，缩进 TXT 不生成重复歌词；人工确认的文字和时间受到保护。

下一轮重点是在真实可用的人声音轨上完成模型下载/加载与歌唱识别的端到端验证，记录实际硬件、模型版本、参数、候选时间偏差和人工校正成本；再完善高精度强制对齐、长曲性能、更多节奏排版和桌面打包。

## 完整 V1.0 技术方案

| 层 | 规划 |
| --- | --- |
| 表现层 | React + TypeScript；播放器、波形、歌曲结构、谱面与编辑界面 |
| 服务层 | Python + FastAPI；音频导入、后台分析任务、工程持久化与导出 |
| 模型适配层 | 统一输入输出、模型可用性检查、错误提示、进度与结果来源；允许替换分析模型 |
| 存储层 | SQLite 管理本地曲库元数据；本地音频与 JSON 保存工程及编辑内容 |
| 桌面层 | Web 工作流稳定后，评估 Tauri 打包；保持离线编辑和本机分析能力 |

技术候选包括 FFmpeg 解码、Demucs/HTDemucs 分离、librosa 或 Essentia 节拍特征、All-In-One 结构分析、Chordino/Chroma 和声分析、Basic Pitch 贝斯转写、Whisper/faster-whisper 识别、WhisperX 对齐及 WaveSurfer 波形展示。它们是评估队列，不表示当前已全部安装或集成。每个模型应先验证 Windows/Python/PyTorch 兼容性、许可证、内存占用、CPU/GPU 处理时间，再决定纳入基础或可选安装。

## 统一时间与数据契约

完整方案包含 Song、Stem、TempoMap、Measure、Section、ChordEvent、LyricToken、BassNote、Fill、Tone 和 Chart。时间事件根据类型保存开始/结束时间、小节/拍点、内容、置信度和人工修改标记，同时保留结果来源。

基本映射为“歌词字词或片段 → 音频时间 → 小节/拍点 → 和弦事件”。歌词不应被限制为每句只对应一个和弦。修改节拍网格后应保留歌词和和弦的实际音频时间，再重算小节/拍点；修改音频定位的事件必须直接反馈到谱面与导出。

当前工程用 Project、Stem、Section、Chord、Lyric、Note、Marker 和 Analysis 表达这些基础关系。Chord 保存明确时间区间；JSON 是完整工程数据来源，SQLite 保存可重建索引。后续补齐细分对象时需提供兼容迁移，保护既有人工修改与旧工程导入。

## V0.1 验收清单

- 常见音频格式可导入、解码与试听，分离后的可用轨道可试听和导出。
- 可修正 BPM、半速/倍速、第一拍、拍号与段落边界。
- 和弦绑定具体拍点和时间区间，一小节内可有多个和弦，允许人工校正。
- LRC 时间标签映射到小节/拍点；歌词时间与和弦对位可人工调整。
- 可生成打印排练谱、独立 HTML、JSON 工程与 LRC。
- 保存并重新打开工程后，人工修改仍保留；旧版本保存冲突明确提示。
- 模型缺失、分析失败、服务重启导致任务中断时，明确说明状态与后续操作。

自动人声识别与精确逐字对齐属于可选增强，不阻塞首版以 LRC/手工歌词完成上述流程。

## 准确性与效率评估

准备 30 首有使用授权的测试歌曲，覆盖中文、英文、日文流行曲及不同节奏/编配；其中另选 5–10 首建立人工精标基准。测试素材、授权范围、硬件、模型版本、参数与人工编辑时间须记录。

按统一评估流程统计分离听感、BPM 与小节偏差、段落边界误差、和弦准确率、歌词时间偏差、音符 F1、人工校正时间与处理耗时。模型输出的置信度不应直接当作准确率。当前尚未完成这套真实歌曲基准，不发布未经测量的准确率或效率提升数字。
